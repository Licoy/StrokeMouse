# 제스처

안정적인 사용자 제스처를 위한 트리거, 샘플링, 일치 규칙입니다. 스크롤 반전과 부드럽게는 제스처 라이브러리에 없습니다. [설정과 메뉴 막대](./settings#scroll-enhancement)를 보세요.

## 파이프라인

```text
트리거 유지 → 경로 샘플 → 거리 ≥ 최소 스트로크
     → 손 뗌 → 같은 트리거 후보에서 일치 → 동작 실행
```

1. **트리거는 각 제스처 프로필에 있습니다**(기본값 오른쪽 버튼)
2. 엔진은 **활성화된** 제스처가 쓰는 버튼만 감시합니다
3. 손을 떼면 **앱 범위** + 전면 `bundleIdentifier`가 후보를 걸러 냅니다

## 트리거

제스처마다:

| 트리거 | 설명 |
|---------|--------|
| 오른쪽 | 기본값; 짧은 클릭은 컨텍스트 메뉴를 엽니다 |
| 가운데 | 휠 클릭 |
| 측면 뒤로 / 앞으로 | 일반적인 엄지 버튼 |

왼쪽 버튼과 감시하지 않는 버튼은 **항상** 통과합니다.

## 마우스 버튼 매핑

**추가 → 마우스 버튼**에서 측면 버튼(뒤로 / 앞으로)이나 가운데 버튼에 매핑을 만들면, 그리지 않아도 버튼을 한 번 클릭하는 것만으로 동작이 실행됩니다. 메뉴에는 「뒤로 측면 버튼 · 뒤로 가기」(⌘[)와 「앞으로 측면 버튼 · 앞으로 가기」(⌘]) 프리셋이 들어 있습니다.

- 버튼을 놓을 때 실행됩니다. 같은 버튼을 마우스 그리기에도 쓰면 `minStrokeDistance` 미만은 클릭으로 매핑을 실행하고, 넘으면 그리기로 인식하므로 한 번 누름으로 둘 다 실행되지 않습니다
- 대상 앱에 그 버튼의 매핑만 있고 그리기 제스처가 없으면, 누른 채 움직여도 클릭으로 처리합니다
- **보조 키 함께 누르기**를 켜고 Fn / Control / Option / Shift / Command 중 하나를 고르면 그 키 하나만 누른 상태에서만 실행됩니다(예: ⌘ + 뒤로 측면 버튼). 이 옵션이 꺼진 매핑은 보조 키를 누르고 있는 동안 실행되지 않으므로 한 버튼에 일반 매핑과 보조 키 매핑을 함께 둘 수 있습니다. 선택한 보조 키를 트랙패드 그리기에도 쓰면 트랙패드 그리기가 우선하여 매핑은 실행되지 않습니다
- 전체 / 앱 그룹 / 선택한 앱 범위를 그대로 따르며 가장 구체적인 단계만 사용합니다. 같은 단계에 매핑이 여러 개면 충돌로 보고 실행하지 않고 알립니다
- 대상 앱에 그 버튼의 제스처나 매핑이 없으면 버튼은 그대로 통과합니다(예: 브라우저 기본 뒤로 / 앞으로 유지)
- 컨텍스트 메뉴를 막지 않도록 오른쪽 버튼은 매핑할 수 없습니다. 매핑이 실행되어도 일치 알림은 표시하지 않습니다

## 마우스 조합

**추가 → 마우스 조합**에서 만듭니다. 궤적을 녹화할 필요가 없으며 모든 동작, 대상 창, 범위를 그대로 씁니다.

| 트리거 | 마우스 동작 | 실행 시점 |
|--------|------|------|
| 오른쪽 버튼 누르기 | 위로 / 아래로 스크롤 | 휠 한 칸마다 한 번, 반복 실행 가능 |
| 오른쪽 버튼 누르기 | 왼쪽 클릭 | 오른쪽 버튼을 누를 때마다 첫 왼쪽 클릭에서만 |
| 화면 가장자리(위 / 아래 / 왼쪽 / 오른쪽) | 오른쪽 클릭 | 선택한 가장자리에서 오른쪽 버튼을 눌렀다 놓고, 그리기를 시작하지 않았을 때 |
| 화면 가장자리(위 / 아래 / 왼쪽 / 오른쪽) | 위로 / 아래로 스크롤 | 오른쪽 버튼 없이, 최대 100ms마다 한 번 |

- 조합을 실행한 오른쪽 버튼 누름이나 클릭은 컨텍스트 메뉴를 열지 않고 그리기로도 인식하지 않습니다. 조합이 실행되지 않은 오른쪽 클릭은 평소처럼 메뉴를 엽니다
- 「오른쪽 버튼 누르기 + 왼쪽 클릭」은 보조 동작보다 우선하며, 이 조합이 없으면 보조 동작은 기존대로 동작합니다
- 설정하지 않은 휠 방향과 조합이 없는 앱은 평소처럼 스크롤됩니다. 조합이 사용한 휠 입력은 페이지를 스크롤하지 않습니다
- 오른쪽 버튼을 누른 동안 고정밀 휠은 동작 간격이 최소 120ms이므로 한 번의 스크롤로 여러 탭이 넘어가지 않습니다. 트랙패드, 관성 스크롤, 다른 스크롤 도구가 보내는 부드러운 프레임은 동작을 실행하지 않습니다
- 가장자리는 각 디스플레이 경계 안쪽 3포인트이며, 인접한 디스플레이 사이의 이음새도 포함합니다. 모서리에서 같은 단계의 설정 두 개가 일치하면 충돌로 처리합니다
- 범위와 충돌 규칙은 마우스 버튼 매핑과 같습니다. 가장 구체적인 단계만 사용하고, 같은 단계에 여러 개가 있으면 충돌로 보고 실행하지 않고 알립니다. 앱 정책에서 전체 「마우스 조합」만 따로 끌 수 있습니다

## 짧은 클릭 재생

엔진이 트리거-다운을 잡은 뒤:

- 거리가 `minStrokeDistance` **미만**: 표시된 합성 down/up이 일반 클릭을 **재생**합니다(메뉴가 동작). 대상 앱에 그 버튼의 매핑이 있으면 대신 매핑을 실행합니다
- 실제 스트로크가 시작되면: down/drag/up 그룹은 **제스처 전용**이며 전면 앱으로 전달되지 않습니다

## 자유 경로 일치

기본 인식기:

- 순서 있는 호 길이 재샘플
- 1D / 2D 정규화
- **±12°** 제한 회전 검색
- 점수 ≥ 임계값
- **구간 수 / 꺾임 구조**를 점수로는 보상할 수 없는 하드 게이트로 사용
- 거울, 역순, near-miss 폴백 **없음**

중간 속도로 깨끗한 궤적을 녹음하세요. 복잡한 모양은 안정될 때까지 다시 녹음합니다.

## 실시간 HUD

트리거를 누르는 동안 현재 경로가 화면에 그려져 템플릿에 맞출 수 있습니다.

## 앱 범위

| 범위 | 동작 |
|-------|----------|
| 전역 | 어떤 전면 앱에서든 일치 |
| 특정 앱 | 전면 앱이 목록에 있을 때만 |

편집기에서 **설치된 앱을 아이콘으로** 고릅니다(검색, 다중 선택, `.app` 찾아보기). bundle id를 손으로 칠 필요는 없습니다(일치는 내부적으로 bundle identifier를 씁니다). 브라우저 전용이나 IDE 전용 제스처에 씁니다.

제스처 목록 범위 열은 「전역」 또는 앱 아이콘 요약을 보여 줍니다. **설정 → 제스처**의 왼쪽 사이드바는 전역과 앱별 그룹을 탐색합니다. 노드 아래에서 만들면 해당 범위가 미리 채워집니다.

## 사용 / 사용 안 함

제스처마다 토글합니다. 끈 프로필은 감시 집합과 일치 풀에서 빠집니다.
