# ジェスチャ

安定したカスタム軌跡のためのトリガー、サンプリング、マッチング規則です。スクロールの反転とスムーズ化はジェスチャライブラリにはありません。[設定とメニューバー](./settings#scroll-enhancement) を見てください。

## パイプライン

```text
トリガーを押したまま → 経路をサンプル → 距離 ≥ 最小ストローク
     → 離す → 同じトリガーの候補から一致 → アクション実行
```

1. **トリガーは各ジェスチャプロファイルにあります**（デフォルトは右ボタン）
2. エンジンは**有効な**ジェスチャが使うボタンだけを監視します
3. 離すと **App 範囲** + 最前面の `bundleIdentifier` が候補を絞ります

## トリガー

ジェスチャごと:

| トリガー | メモ |
|---------|--------|
| 右 | デフォルト。短押しでもコンテキストメニューは開く |
| 中 | ホイールクリック |
| サイド戻る / 進む | 一般的な親指ボタン |

左ボタンと監視していないボタンは**常に**通過します。

## マウスボタン割り当て

**追加 → マウスボタン** でサイドボタン（戻る／進む）または中ボタンに割り当てを作ると、描画せずにボタンをクリックするだけでアクションが実行されます。メニューには「戻るサイドボタン · 戻る」（⌘[）と「進むサイドボタン · 進む」（⌘]）のプリセットがあります。

- ボタンを離したときに実行します。同じボタンをマウス描画にも使う場合、`minStrokeDistance` 未満ならクリックとして割り当てを実行し、超えると描画として認識するため、1 回の押下で両方が実行されることはありません
- 対象アプリにそのボタンの割り当てだけがあり描画ジェスチャがない場合、押したまま動かしてもクリックとして扱います
- **修飾キーの同時押しが必要**をオンにして Fn / Control / Option / Shift / Command から 1 つ選ぶと、そのキーだけを押しているときのみ実行されます（例：⌘ + 戻るサイドボタン）。オフの割り当ては修飾キーを押している間は実行されないため、同じボタンに修飾キーなしとありの割り当てを両方置けます。選んだ修飾キーをトラックパッド描画にも使う場合はトラックパッド描画が優先され、割り当ては実行されません
- グローバル／アプリグループ／選択したアプリの範囲をそのまま使い、最も具体的な階層だけが対象です。同じ階層に複数の割り当てがあると競合として扱い、実行せずに通知します
- 対象アプリにそのボタンのジェスチャも割り当てもない場合、ボタンはそのまま通過します（例：ブラウザ標準の戻る／進むを維持）
- コンテキストメニューを妨げないよう右ボタンは割り当てできません。割り当てが実行されても一致の通知は表示しません

## マウスの組み合わせ

**追加 → マウスの組み合わせ** で作成します。軌跡の記録は不要で、すべてのアクション、対象ウインドウ、範囲をそのまま使えます。

| トリガー | マウス操作 | 実行タイミング |
|--------|------|------|
| 右ボタンを押しながら | 上／下にスクロール | ホイール 1 目盛りごとに 1 回、連続実行できます |
| 右ボタンを押しながら | 左クリック | 右ボタンを押すたびに最初の左クリックのみ |
| 右ボタンを押しながら | ドラッグでスクロール | ポインタが 10 ポイント以上動くと縦横にスクロールし、離すと停止 |
| 画面の端（上／下／左／右） | 右クリック | 選んだ端で右ボタンを押して離し、描画を始めていないとき |
| 画面の端（上／下／左／右） | 上／下にスクロール | 右ボタンは不要、最大 100 ミリ秒に 1 回 |

- 組み合わせを実行した右ボタンの長押しやクリックでは、コンテキストメニューは開かず描画としても認識しません。組み合わせが実行されなかった右クリックでは通常どおりメニューが開きます
- 「右ボタンを押しながら + 左クリック」は第2アクションより優先されます。この組み合わせがなければ第2アクションは従来どおり動作します
- 設定していないホイール方向や組み合わせのないアプリは通常どおりスクロールします。組み合わせが使ったホイール入力ではページはスクロールしません
- 右ボタンを押している間、高精度ホイールのアクションは最短 120 ミリ秒間隔になり、1 回のスクロールで多数のタブが切り替わることはありません。トラックパッド、慣性スクロール、他のスクロールツールが送るスムーズ化フレームではアクションを実行しません
- 端は各ディスプレイの境界から内側 3 ポイントで、隣接するディスプレイの継ぎ目も含みます。角で同じ階層の設定 2 つに一致した場合は競合として扱います
- 範囲と競合のルールはマウスボタン割り当てと同じです。最も具体的な階層だけが対象で、同じ階層に複数あると競合として扱い、実行せずに通知します。アプリポリシーでグローバルの「マウスの組み合わせ」だけを停止することもできます

**ドラッグでスクロール**: 「右ボタンを押しながら」で「ドラッグでスクロール」を選び、「感度」（0.25–4 倍、0.05 刻み）と「方向を反転」を調整できます。標準では内容がポインタに追従します。右ボタンを押してからポインタが固定の 10 ポイント以上動くとスクロールが始まり、「最小ストローク距離」には従いません。それより前に離すと通常の右クリックが再生されるためコンテキストメニューは使えます。スクロールが始まったあとは、離してもクリックの再生や描画の認識は行いません。スクロールするのは開始時にポインタの下にある内容で、ウインドウは前面にしません。アプリ範囲の判定には、右ボタンを押した時点で固定したターゲットを使います。離すとすぐに停止し、慣性、ポインタ固定、中央への戻しはないため、画面端で移動量が制限されます。通常のアクションや第2アクションはないため、保存してからエディタの外で右ボタンを押しながら動かして試してください。

最も具体的な範囲の階層（アプリ > アプリグループ > グローバル）では、ドラッグでスクロールは右ボタンの描画や別のドラッグでスクロールと共存できません。実行時にこの競合が起きると何も実行せず、専用の通知を表示します。グローバル同士、アプリ一覧が重なる場合、同じアプリグループといった確定的な競合はすべての操作で防がれます。エディタでの保存、チェックボックスや一括操作での有効化、「移動先」、ジェスチャをグローバルとして残すアプリグループの削除は競合するジェスチャを示して中止されます。「複製」で競合する場合はコピーを無効状態で作成し、読み込みでは競合するジェスチャを無効状態で取り込んで一覧表示します。すでに競合している有効なジェスチャ（バックアップの復元後など）には、ジェスチャ一覧で警告アイコンが表示されます。既存のジェスチャが削除されたり自動で無効になったりすることはなく、異なるアプリグループ間の動的な重なりは引き続き実行時に判定します。

## 短押し再生

エンジンがトリガーダウンを捉えたあと:

- 距離が `minStrokeDistance` **未満**: 印付きの合成 down/up が通常クリックを**再生**します（メニューは動く）。対象アプリにそのボタンの割り当てがあれば、代わりに割り当てを実行します。右ボタンの「ドラッグでスクロール」が使える場合、しきい値は固定の 10 ポイントになります
- 本格的なストロークまたはドラッグでのスクロールが始まると: down/drag/up グループは**ジェスチャ専用**で、最前面 App には渡りません

## 自由軌跡マッチング

主な認識器:

- 順序付き弧長リサンプル
- 1D / 2D 正規化
- **±12°** の制限付き回転探索
- スコア ≥ しきい値
- **セグメント数 / 折れ曲がり構造**をスコアでは補償できないハードゲートにする
- 鏡像、逆順、near-miss フォールバックは**使わない**

中くらいの速さできれいな軌跡を録ってください。複雑な形は安定するまで録り直します。

## ライブ HUD

トリガーを押している間、現在の経路が画面に描かれ、テンプレートに合わせやすくなります。

## App 範囲

| 範囲 | 動作 |
|-------|----------|
| グローバル | どの最前面 App でも一致 |
| 特定 App | 最前面 App がリストにあるときだけ |

エディタでは**インストール済み App をアイコンで**選びます（検索、複数選択、`.app` を参照）。bundle id を手入力する必要はありません（照合は内部で bundle identifier を使います）。ブラウザ専用や IDE 専用のジェスチャに使います。

ジェスチャ一覧の範囲列は「グローバル」または App アイコンの要約を表示します。**設定 → ジェスチャ**の左サイドバーはグローバルと App ごとのグループを閲覧します。ノードの下で作ると、その範囲が事前入力されます。

## 有効 / 無効

ジェスチャごとのトグルです。無効なプロファイルは監視集合とマッチングプールから外れます。
