# 真实小写 a 曲线识别修复

## 问题与证据

开发回归数据来自 `RecordedCurveAGestureFixture.json`，其中 1–7、10、11 共 9 条经轨迹外观复核为同形小写 a；8、9 保留为 `unknownIntent`，几何上与 a 不等价，但没有推断用户当时想画什么。这 9 条同形 a 来自同一批已知数据，不是独立盲测。

旧算法把等弧长采样后的同序号点直接比较。真实重画会改变环、折返和末笔在总弧长中的占比，即使轨迹的顺序与方向一致，同一个局部结构也可能落到相邻的采样序号，点距因此占总成本的 92%–95%。这属于局部形状和弧长比例错位，不是绘制速度差。

第二条轨迹还有一个独立的结构问题。折返点附近的切线跨过 `±π` 分支，原始单步转角约为 `-162°`，而模板对应位置约为 `+142°`。重新采样后，这个折返点可能变成约 `-138°`，也可能拆成相邻的 `-87°/-62°`。旧的 turn-run 过滤随后把相邻转向错误抵消，产生 `turnDirection` 拒绝。

## 修复

曲线评分改为首尾锚定的有限有序对齐：64 个点，band 为 4，只允许单调前进，连续横步或竖步最多 2 次，不开放头尾，不允许镜像或逆序。局部成本同时包含归一化位置距离和 2、4、8 三个尺度的切线差。对角步权重为 2，横步和竖步权重为 1，最终使用固定的 `2N` 归一化，因此增加 warp 步不会靠扩大分母稀释成本。旋转仍限制在 `±12°`，先用原有同序位置与切线成本选择一个旋转，再执行一次有限对齐。

折返点只在严格的几何条件下稳定符号：同号集中 turn-run 的累计转角至少 `135°`，跨度不超过同一个 band 4；移除它后，其余轨迹累计转角至少 `180°`，且净方向占绝对转角至少 80%。满足这些条件时，集中 run 使用主体曲线的转向符号。逆序和镜像轨迹的主体方向会一同反转，方向拒绝仍然保留；接近零净转向或多个 cusp 的轨迹不会被改写。

有限对齐不能吞掉超出 band 的直线尾巴。签名使用 2、4、8 三尺度切线，记录最后一个稳定转向后的采样跨度；稳定转向门槛由现有最小 run 转角 `12°` 除以 band 4 得到 `3°`。若候选比模板多出超过 4 个末端直线 turn，匹配以 `terminalOverrun` 拒绝。这个约束与对齐带宽使用同一单位，没有新增字形或手势 ID 特判。

旋转选择后还会用同一个已选旋转检查首末切线，分别复用既有 `30°` 起点和 `45°` 终点方向门槛。这个检查不会为起点和终点各自挑选有利旋转。9 条同形 a 的旋转后起点差为 `0.80°–26.51°`，终点差为 `1.44°–41.06°`；带 `75°` 新首转折的负例起点差为 `68.07°`，带 `70°` 新尾段的负例终点差为 `48.51°`，两者分别以 `startDirection` 和 `endpointDirection` 拒绝。

算法版本由 `curve-signature-v1` 升为 `curve-signature-v2`。v1 日志只能按当前算法重新评估，不能标记为精确重放。

新距离尺度的选择同时受正负例约束。已知同形 a 及其确定性派生变体中的最大距离为 `0.0828615`，要在 `0.70` 阈值通过，尺度下界为 `0.232319`。端点方向门控加入前，用于尺度校准且未被当时结构门直接归零的合成负例中，最小距离为 `0.405551`（O 的错误起点）；要保持低于 `0.60`，尺度上界为 `0.793902`。后续端点门控可能会更早归零该负例，因此这个上界是保守的校准证据，不表示它仍是最终实现中最小的非零负例。最终选择 `0.24`，接近正例侧，同时保留较大的负例距离余量。这个区间来自开发语料，不能替代独立盲测。

## 验证边界

验证覆盖 9 条同形 a 的原始轨迹、平移、统一缩放、固定种子的轻微点抖动和不同重采样密度，并覆盖第 8、9 条几何不等价轨迹、其他已记录候选、逆序、镜像、截断、额外尾巴和旧有合成曲线矩阵。U 形曲线的 15%/20% 同向尾巴还覆盖多个固定 seed、`0.1/0.5 px` 抖动和 64/97/160 点输入密度。

9 条同形 a 在最终算法下的原始轨迹分数依次为 `0.820918`、`0.722127`、`0.770218`、`0.721846`、`0.738254`、`0.747746`、`0.789730`、`0.754387`、`0.784784`；第 8、9 条保持 `0`。最终完整 Debug 套件执行 621 项，3 项 opt-in 测试跳过，0 failures；独立 Debug build 也以 exit 0 完成。跳过项中的两个性能测试已在 Release 配置单独执行，2 项、0 failures；另一个是本次无 UI 改动的样本编辑器截图测试。

本轮代码验证已完成全量 Debug 测试、独立 Debug build，以及 50 profiles × 3 samples 的 Release 结束识别和 live P95；100 × 5 仅记录压力数据。可测试产物位于 `output/curve-a-fix/StrokeMouse.app`，二进制包含 `curve-signature-v2`，Bundle ID 为 `com.strokemouse.app.dev`；`codesign --verify --deep --strict` 在本机信任上下文中以 exit 0 通过，显示 `valid on disk` 与 `satisfies its Designated Requirement`。本轮没有启动新包，也没有关闭用户正在运行的旧应用。不同真实设备、个人绘制习惯及实际硬件上的独立重画仍需用户人工验收，代码、测试、构建与本机验签不能替代这一步。

实时 HUD 保留严格同序的模板前缀评分，不使用终态的有限对齐。只要已有可恢复候选达到 hope 阈值，就可以立即返回 `viable`，其余候选不能推翻这个二值结果。这样，同形 a 的逐步绘制不会连续 3 次进入 `unlikely`，未闭合 O 仍为 `viable`，长锯齿对 O 仍为 `unlikely`。终态的尾巴和端点方向门控不受 HUD 乐观评分影响。

HUD 的前缀搜索只需要回答是否达到 hope 阈值。其距离为 `positionAverage + 0.08 × tangentAverage`，切线项非负，因此位置平均距离是最终距离的下界。hope 分数可换算为最大允许距离 `-log(hope) × 0.18`；一旦累计位置距离已经超过这个预算，即使剩余位置与切线成本全为零也不可能达标，可以停止当前旋转。任一旋转或模板前缀达标后也可以立即返回。这个剪枝不改变二值 viability 结果。

Release 性能分别测量三类路径：50 profiles × 3 samples 的完整合成曲线、同规模真实 a 绘制中段，以及所有候选均不匹配的长锯齿；100 × 5 记录相同压力场景。负例无法依靠正例早退，是 HUD 前缀搜索的最慢路径，因此不能只用完整匹配曲线的数字代表 live 性能。

最终 Release P95 如下，单位为毫秒：

| 场景 | 50 × 3 | 100 × 5 |
|---|---:|---:|
| 合成完整曲线 end | 4.013792 | 13.248083 |
| 合成完整曲线 live | 0.139750 | 0.125833 |
| 真实 a end | 4.736417 | 15.248500 |
| 真实 a 40% prefix live | 0.063792 | 0.060209 |
| 真实 a 60% prefix live | 0.094708 | 0.090917 |
| 完全不匹配负例 live | 3.796916 | 11.974667 |

要求的 50 × 3 边界全部通过：end 低于 30 ms，live 低于 8 ms。100 × 5 只作压力记录，不设通过阈值。剪枝前 50 × 3 完全不匹配负例 live P95 为 `15.437334 ms`，加入确定性的距离下界剪枝后降为 `3.796916 ms`。
